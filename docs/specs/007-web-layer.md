# 007. Веб-слой и привратник запросов

Статус: черновик (5 ноября 2026). Реализовано и проверено 5 ноября: привратник адреса, лимиты, хранилище, маршруты, страницы (английский интерфейс), подтверждения; 32 теста и 23 мутации пойманы, живая проверка на сервере с настоящими ВМ и моделью. Позже в тот же день: вкладки отчёта в духе Cloudflare Radar, служба systemd, Caddy и TLS (работает на `zerostress.space`), обнаружение «стен» (3.9). Не сделано: кэш и прогрев (3.8), вывод собранного при стене и признак «стена» (3.9), проверка подтверждения на живой ВМ. Решения по доступу и по каналу к браузеру приняты 5 ноября 2026 (раздел 2).

## 1. Цель и границы
Принять адрес от человека в браузере, поставить проверку, показывать ход и отчёт, дать владельцу задачи подтвердить или отменить рискованное действие. Область: каталог `web/server/` (непривилегированный слой хоста, Node, TypeScript без сборки, фреймворк Hono). Не входит: агент, хуки, отчёт (008, 009, `web/agent/report.ts`), супервизор (006), прокси и TLS (010).

Правила из CLAUDE.md, которые здесь действуют: ключи только в окружении службы (2); лимиты (3); недоверенный вывод остаётся данными (7); решения о допуске запросов принимает код (8); подтверждение рискованного действия даёт человек, никогда агент.

## 2. Решения
| Вопрос | Решение | Почему |
|---|---|---|
| Доступ судей | **без кода доступа**, открыто всем (решение пользователя) | меньше трения для судей; цена: расходы закрываем лимитами и общим потолком (раздел 5), а не кодом |
| Канал к браузеру | **SSE**, как у супервизора | поток идёт в одну сторону, команды человека идут обычными POST; автопереподключение и `Last-Event-ID` уже в браузере и в супервизоре; WebSocket не нужен |
| Язык | Node и TypeScript, как остальной слой `web/` | хуки, агент и отчёт уже там; переписывание на Go ради SSE не нужно |
| Фреймворк | Hono на Node (`@hono/node-server`), версии закреплены в лок-файле, установка `npm ci --ignore-scripts` | готовая маршрутизация, заголовки и SSE; писать вручную нечего; проектное (проверка адреса, экранирование, лимиты) остаётся нашим кодом |
| Страницы | серверный рендер HTML, один небольшой файл `app.js` для потока и кнопок | экранирование в одном месте |
| Кто подтверждает | **тот, кто создал задачу**, по секретному ключу задачи (3.2) | кода доступа нет, поэтому право решать привязано к задаче, а не к человеку |
| Хост не ходит по адресу | веб-слой **не разрешает DNS и не открывает адрес**; это делает только гость | серверной подделки запроса (SSRF) со стороны хоста нет по построению; сеть гостя закрыта отдельно (003) |

## 3. Как работает

### 3.1 Процесс
Одна служба `zerostress-web` от пользователя `zsweb`, слушает `127.0.0.1:<порт>`; снаружи Caddy (010). Внутри: привратник запросов, реестр задач, исполнитель `runTask` (008) в том же процессе, клиент супервизора по Unix-сокету, отдача страниц и потока.

### 3.2 Задача и ключи
`POST /api/tasks` создаёт задачу и возвращает `task_id` (128 бит случайных, публичный: по нему открывается отчёт) и `key` (256 бит, секретный: даёт право подтверждать и отменять). Ключ показывается один раз; страница кладёт его во фрагмент адреса (`/r/<task_id>#k=<key>`), который не уходит на сервер, в журналы и в `Referer`. Браузер шлёт ключ заголовком `X-Task-Key`. Сервер хранит только SHA-256 ключа и сравнивает постоянным по времени сравнением. Ссылкой без ключа можно делиться: она только читает публичный отчёт.

### 3.3 Привратник запросов (по порядку, первый отказ заканчивает)
1. Метод и путь из списка; тело не больше 4 КиБ; `Content-Type: application/json`; заголовок `Origin` равен нашему адресу (против чужих страниц, шлющих форму); лишние поля отвергаются.
2. Лимиты (раздел 5).
3. **Проверка адреса** (чистая функция, отдельный модуль, самые строгие тесты):
   - разбор стандартным `new URL`, схема только `http` и `https`, длина не больше 2048, без `user:pass@`, без управляющих символов и пробелов;
   - имя хоста после разбора: `localhost`, `*.localhost`, `*.local`, `*.internal`, `*.localdomain`, имя из одной метки (без точки), пустое отвергаются;
   - если хост это IP в любой записи (десятичное число, восьмеричное, шестнадцатеричное, сокращённое, `[::ffff:a.b.c.d]`): адрес приводится к канону и сверяется со списком закрытых диапазонов: `0.0.0.0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16` (включая `169.254.169.254`), `172.16/12`, `192.0.0/24`, `192.168/16`, `198.18/15`, `224/4`, `240/4`, `::`, `::1`, `fc00::/7`, `fe80::/10`, `ff00::/8`, а также IPv4, встроенный в IPv6 (`::ffff:`, `64:ff9b::`, 6to4);
   - порт: только пусто, 80, 443, 8080, 8443 (остальные дают `bad_port`; список в одном месте, меняется по решению);
   - итог: нормализованный адрес, его и передаём дальше (не исходную строку).
4. Постановка в исполнитель; ответ `202` с `task_id`, `key`, позицией в очереди.

Проверка адреса это **первая линия, не единственная**: DNS-имя, указывающее на закрытый адрес, и редиректы привратник не видит, их останавливает сеть гостя (003, containment 5).

### 3.4 Ход и поток к браузеру
`GET /api/tasks/{id}/events` отдаёт SSE (`id`, `event`, `data`) в нашем составе, а не сырые события супервизора:
- `state` (очередь, позиция, загрузка, работа, готово, сбой), `step` (действие и статус, формулировка кода), `final` (публичный отчёт целиком), `approval` (ожидает подтверждения, см. 3.6);
- улики, текст страницы и ответы модели в поток не идут: их читает только отчёт, и только через список `UNTRUSTED`.
Для завершённой задачи поток воспроизводится из сохранённого результата. Каждые 15 секунд `:keepalive`. Отключение клиента задачу не отменяет.

### 3.5 Отчёт
`GET /r/{id}`: с 6 ноября 2026 страницу собирает клиент (спека 012) из `GET /r/{id}/report.json` и `GET /api/tasks/{id}`; сервер отдаёт для адресов страниц только собранный `index.html`. Правила показа те же, их проверяют тесты клиента:
- каждое поле из `UNTRUSTED` проходит одну функцию экранирования и попадает только в текстовые узлы; в атрибуты, адреса ссылок, стили и скрипты недоверенный текст не попадает никогда;
- адрес проверяемой страницы показывается **текстом**, а не ссылкой (кто-то из судей мог бы щёлкнуть по вредоносному адресу в своём браузере);
- `app.js` пишет в страницу только через `textContent` и `createElement`, `innerHTML` и `eval` запрещены (проверяется поиском по файлу в тесте);
- заголовки на каждом ответе: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` (для отчётов и потока), `Cross-Origin-Opener-Policy: same-origin`;
- скриншот: `GET /r/{id}/screenshot.png`, байты берутся у супервизора (имя только из списка `shot*.png`, размер не больше `SHOT_MAX`, сигнатура PNG проверяется ещё раз), ответ `image/png` с `nosniff` и `Content-Security-Policy: sandbox`.
Версия для владельца сервиса (`ownerReport`) через публичный порт **не отдаётся**: отдельный слушатель на `127.0.0.1:<порт-админа>`, доступ по SSH-туннелю, без токенов в этом слое.

### 3.6 Подтверждение человеком
Страница показывает ожидающее действие, собранное **кодом** из команды (действие, хост цели, имена полей, но не значения, введённые моделью, и не текст страницы). Кнопки «Разрешить» и «Отклонить» шлют `POST /api/tasks/{id}/approvals` с `command_id`, `command_sha256` и `X-Task-Key`. Веб-слой проверяет ключ и что пара `command_id`+хеш есть среди ожидающих, и передаёт в `POST /v1/runs/{run_id}/approvals` супервизора (006, 3.8), где хеш и срок проверяются ещё раз. Ответы супервизора `409` и `410` показываются как «действие уже изменилось» и «срок вышел». Подтверждённое действие не шире показанного, потому что хеш привязывает именно эту команду. Отмена: `DELETE /api/tasks/{id}` с ключом.

Нужно дописать в клиент супервизора метод `approve(runId, commandId, sha256)`, сейчас его там нет.

### 3.8 Кэш, прогрев и список примеров (предложение, не реализовано)
- **Кэш по нормализованному адресу.** Если тот же адрес (после привратника, без `#`) проверен меньше `WEB_CACHE_MIN` минут назад (предложение: 60) и проверка была обычная, а не «глубокая», отчёт отдаётся готовым без новой ВМ. Страница показывает «Проверено N минут назад» и кнопку «Проверить заново» (она идёт через обычные лимиты). Цель: меньше расходов на ВМ и модель, мгновенный ответ на повторы. Риск: устаревший вердикт у страницы, которая изменилась; поэтому срок короткий и возраст виден.
- **Прогрев.** Список безопасных адресов (демо-страницы, раздел 9 в TOOLS.md) в настройке `WEB_WARM` проверяется службой по расписанию (предложение: раз в сутки, и один раз при старте), с паузой между запросами и с тем же лимитом одновременных ВМ, что у людей (расходуют отдельный маленький бюджет, не лимиты посетителей). Результаты лежат в обычном хранилище и не удаляются по сроку, пока адрес в списке.
- **Список примеров на главной,** как «Recent public scans» у Cloudflare: таблица прогретых адресов (адрес, вердикт, время проверки), клик открывает готовый отчёт без ожидания. Это то, что судья увидит первым, даже если ВМ заняты.
- Ссылки пользователей в этот список **не попадают** и из кэша третьим лицам не показываются: кэш используется только тому, кто сам прислал тот же адрес, а таблица содержит только прогретый список.
- Сравнение со сторонними сканерами для прогретых адресов: TOOLS.md, раздел 2а (условия не подтверждены, пока не включено).

### 3.9 Страницы за «стеной» (решено 5 ноября 2026, часть реализована)
**Что это.** Проверка «вы человек» (Cloudflare, DataDome, Turnstile), ответ 401/403/404/410/429/451/5xx на основной документ, пустая страница. Сборщик видит стену, а не сайт.

**Реализовано** (`web/agent/signals.ts`, `assess.ts`): сигналы `bot_challenge`, `http_error` (с номером), `empty_page`; вердикт `unknown` («не удалось проверить»), если иных признаков нет; модель по такой странице не спрашивается (`page_not_read`); отчёт объясняет, что видели стену. Проверено на записях настоящих страниц (g2.com, glassdoor.com, indeed.com, nowsecure.nl, example.com), 15 мутаций пойманы.

**Решения.**
| Вариант | Решение | Почему |
|---|---|---|
| Решать капчу автоматом | **нет** | обход защиты владельца сайта; ссылка уходит стороннему решателю (утечка); нужна маскировка под человека; дорого и ненадёжно |
| Дать человеку решить капчу (удалённый просмотр ВМ, как в ANY.RUN) | **нет**, в BACKLOG (P2) | крупная функция: поток картинки и ввода, новая поверхность атаки, поверх узкой схемы команд; успеха не гарантирует (стена смотрит на адрес дата-центра и признаки headless) |
| Расширение, читающее открытую страницу | **нет** | страница уже выполнилась у пользователя; приватность |
| Сырой HTML без браузера | как дополнение, не как обход | запрос только из ВМ; на стенах отвечают так же или жёстче; на скриптовых сайтах HTML почти пуст; фишинг может показывать другой контент клиенту без браузера |
| Скриншот | достаточно как доказательство | показывает пользователю, что увидел браузер |

**Предстоит.** (1) Замерить долю стен на 50–100 живых адресах (OpenPhish, URLhaus). (2) При стене показывать всё, что собрано без рендера (редиректы, TLS, домены), сохранить и показать исходный HTML ответа (проверить, хранит ли сборщик тело). (3) Пометить стену как признак: фишинговые наборы прячутся за капчей от сканеров; вердикт остаётся `unknown`. (4) Вход `/?u=<адрес>`. (5) Если стен много: URL Scanner Cloudflare вторым источником с согласия пользователя (TOOLS.md, 2а).

### 3.7 Хранение
Результат задачи пишется в `/var/lib/zerostress-web/tasks/<id>.json` (каталог `StateDirectory` юнита, права 0600, владелец `zsweb`), срок 24 часа, как у супервизора; реестр в памяти. При перезапуске службы задачи в работе помечаются `failed` с причиной `web_restart`. В журнал идут: время, тип события, `task_id`, хост адреса, хеш IP (не сам IP), вердикт; **полный адрес и тексты страниц в журнал не пишутся**.

## 5. Лимиты (все числа в одном файле настроек, значения предложение)
Адрес клиента берётся из заголовка прокси **только если соединение пришло с loopback** (иначе из сокета); IPv6 считается по /64.

| Что | Значение | При превышении |
|---|---|---|
| Новые задачи с одного адреса | 5 в час, 20 в сутки | `429`, `Retry-After` |
| Одновременно активных задач с адреса | 1 | `429`, `too_many_active` |
| Сессии (интерактивный режим) с адреса | 1 в час | `429` |
| Потоков SSE с адреса | 4 | `429` |
| Общий потолок задач в сутки | 300 | `503`, `daily_cap`, страница объясняет, что лимит исчерпан и вернётся в полночь UTC |
| Размер тела запроса | 4 КиБ | `413` |
| Длина очереди | по супервизору (`SUP_QUEUE_MAX`) | `503`, `busy` |
| Токены и запросы к модели | `dailyRequests`, `dailyTokens` из агента (008) | проверка продолжается по правилам без модели |

Цена открытого доступа: любой может занять общий дневной потолок и тем самым закрыть сервис остальным. Принято на время хакатона; смягчение: потолок виден на странице, владелец может поднять его правкой настройки без пересборки.

## 6. Поведение при ошибках
| Ситуация | Поведение |
|---|---|
| Супервизор недоступен | `503`, `supervisor_unavailable`, задача не создаётся |
| Адрес не прошёл проверку | `400` с кодом причины и нашей формулировкой (без повторения адреса в сообщении) |
| Ключа нет или он неверный | `403`, одинаковое сообщение в обоих случаях; не более 10 неверных ключей в минуту с адреса |
| Неизвестный `task_id` | `404`, то же самое и для истёкшей задачи |
| Исполнитель упал или превысил срок | задача `failed`, причина из `TaskResult.failure`; отчёт всё равно строится из того, что есть |
| Поток SSE оборвался | браузер переподключается с `Last-Event-ID`; воспроизведение из сохранённого |
| Модель недоступна | как в 008: режим `rules_only`, причина в отчёте |

## 7. Проверка
Пока список целей, код появится по шагам:
1. **Проверка адреса:** набор «должно отвергнуть» (все записи IP из 3.3, `169.254.169.254` в каждой записи, `localhost`, `[::1]`, `user@host`, управляющие символы, чужие схемы `file:`, `javascript:`, `data:`, `ftp:`) и набор «должно пропустить» (обычные адреса, IDN, длинный путь); мутации: ослабление каждого диапазона по одному.
2. **Лимиты:** часы подставляются, каждая строка таблицы раздела 5 проверяется на границе (последний пропущенный и первый отвергнутый).
3. **Отчёт и экранирование:** страница-ловушка с `<script>`, `"onerror=`, `javascript:` и `</style>` в каждом поле из `UNTRUSTED` (включая каждое из 008); тест требует, чтобы в ответе не было неэкранированных вставок, и проверяет заголовки раздела 3.5; тест «каждое поле из `UNTRUSTED` реально проходит через экранирование» падает, если добавить поле в отчёт, но не в список.
4. **Ключи и подтверждение:** без ключа, с чужим ключом, с неверным хешем, повтор, истёкший срок; чужой ключ не должен подтвердить.
5. **Поток:** состав событий, воспроизведение, `Last-Event-ID`, отсутствие сырых улик в потоке.
6. **Сквозной тест на сервере:** настоящий супервизор и ВМ, безопасная ловушка, от `POST` до отчёта; адрес `http://169.254.169.254/` отвергнут привратником **и** (проверка отдельная) закрыт сетью гостя при обходе привратника.
7. Мутации (`npm run mutate`) по привратнику, лимитам и показу отчёта.

## 9. Открытые вопросы
1. **Что делает исполнитель после подтверждения.** Проверено по коду (`web/agent/runner.ts`, строки 135 и 235): рискованная команда попадает в `pending_approval`, `runTask` **возвращает итог и не ждёт**, сессия остаётся открытой, закрывает её супервизор по простою. Значит, после подтверждения агент сам не продолжает: подтверждённая команда исполняется в сессии супервизором, а её результат веб-слой берёт из событий `command` и дописывает в отчёт. Следствия: (а) срок жизни задачи в реестре веб-слоя дольше возврата `runTask`: он длится, пока жива сессия; (б) для живого журнала в исполнителе нужен обратный вызов `onEvent` (сейчас он отдаёт только итог) и чтение событий `command` после возврата; (в) если после подтверждения нужен новый ход агента (взглянуть на результат), это отдельное решение, в этой спецификации его нет.
2. **Откуда адрес клиента.** За Cloudflare и Caddy нужен заголовок (`CF-Connecting-IP`), и Caddy должен его перезаписывать, иначе его подделают. Решается в 010.
3. **Защита от автоматических запросов** без кода доступа (например, Turnstile у Cloudflare). Пока не закладываем; при злоупотреблении это первая мера.
4. **Нужен ли режим сессии для судей по умолчанию**, или по умолчанию одиночный проход, а сессия по кнопке. Предложение: по умолчанию проход, сессия по кнопке (она занимает слот на минуты).
5. **Значения лимитов** раздела 5 это предложение, а не измерение.
