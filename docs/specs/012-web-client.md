# 012. Клиент веб-слоя: React-приложение на месте серверных страниц

Статус: **черновик**, не согласовано. Спайк сделан 6 ноября 2026 (ветка `spike/web-client`, раздел 8); код клиента не написан. Связано с 007 (веб-слой и привратник), 008 (отчёт и его проекции), 011 (Explain и чат).

## 1. Цель и границы
Сделать интерфейс `zerostress.space` понятным и презентабельным, не потеряв ни одного свойства безопасности страниц из 007, 3.5. Сейчас страницы собираются строками в `web/server/views.ts` (513 строк), поведение — один `static/app.js` (191 строка), стили — `static/style.css`. Это надёжно, но выглядит слабо и плохо расширяется (меню Download, новые вкладки, мобильный вид).

В границах: все страницы, которые видит посетитель (главная, ход проверки, отчёт по вкладкам, Explain и чат, подтверждение владельцем задачи, ошибки), и API, которое им нужно.
Вне границ: логика агента, правила, супервизор; разнесение по машинам (решено: одна машина до сдачи, см. раздел 9); версия отчёта для владельца сервиса (`ownerReport`) по-прежнему не отдаётся наружу (007, 3.5).

## 2. Решение
**Одностраничное приложение (SPA), собранное в статические файлы, на том же адресе, что и API.** Hono остаётся API и отдаёт собранную статику. Отдельного Node-процесса под интерфейс нет, CORS не нужен, CSP та же.

| Часть | Выбор | Версия на 6 ноября 2026 (npm) | Почему |
|---|---|---|---|
| Сборка | Vite | 8.3.6, `@vitejs/plugin-react` 6.2.1 | на выходе только файлы `.js` и `.css`: подходят под `script-src 'self'` без `unsafe-inline` |
| Интерфейс | React | 19.3.1 | экранирует текст по умолчанию: недоверенная строка попадает в текстовый узел, если не открыть `dangerouslySetInnerHTML` (его запрещаем, раздел 6) |
| Маршруты | React Router, Data Mode: `createBrowserRouter` из `react-router`, `RouterProvider` из `react-router/dom` (в v8 пакета `react-router-dom` нет) | 8.5.1 | адреса остаются прежними (`/r/<id>`, `/r/<id>/<вкладка>`, `#k=`); серверный режим (framework mode) не берём: он требует Node-сервер под страницы |
| Запросы | TanStack Query | 5.106.1 | кэш и повторы запросов, состояние загрузки и ошибки без своего кода |
| Стили | Tailwind CSS | 4.3.5 (`@tailwindcss/vite`) | на выходе один файл CSS, своих стилей минимум |
| Компоненты | shadcn/ui (код копируется в проект поверх `radix-ui` 1.8.1), иконки `lucide-react` 1.70.0; **только набор из 6.3**, проверенный спайком | — | доступность (фокус, клавиатура, ARIA) из коробки; компоненты лежат в репозитории и читаются в ревью |
| Тесты | Vitest 5.1.0, Testing Library 16.3.3, jsdom 31.0.0; в браузере — Playwright (уже есть в `collector/`) | — | см. раздел 7 |
| Линтер | ESLint 10 с `eslint-plugin-react` | 10.14.0 / 7.37.5 | правило `react/no-danger` и запрет `href` из недоверенных полей (раздел 6) |

**Не берём:** Next.js и серверный рендер (лишний процесс и поверхность), CSS-in-JS с вставкой стилей во время работы (конфликт с `style-src 'self'`), менеджеры состояния (хватает TanStack Query и состояния компонентов), сторонние шрифты, CDN, аналитику, трекеры и любые запросы с клиента куда-либо, кроме своего адреса.

Каждая зависимость клиента уходит в браузер каждого посетителя, поэтому список выше закрытый: новая библиотека добавляется только решением с записью сюда.

## 3. Как работает
### 3.1 Страницы и путь посетителя
| Адрес | Что видит человек | Откуда данные |
|---|---|---|
| `/` | поле адреса, примеры, короткое «что это и как работает» | список примеров: в сборке или `GET /api/demos` (вопрос 2) |
| `/r/<id>` во время проверки | этапы проверки вживую (очередь и позиция, загрузка, работа), без сведений о нагрузке и серверах | `GET /api/tasks/<id>` (новый, 5.2) и поток `GET /api/tasks/<id>/events` |
| `/r/<id>` после | Summary: вердикт, уверенность, короткое объяснение, скриншот с переключателем компьютер / планшет / телефон, главные находки | `GET /r/<id>/report.json` (публичная проекция, 008) и `/r/<id>/screenshot.png?device=` |
| `/r/<id>/security`, `/network`, `/links`, `/behavior` | вкладки как сейчас | тот же `report.json`, без новых запросов |
| `/r/<id>` при сбое | понятная причина и что делать | `GET /api/tasks/<id>` |
| панель Explain | объяснение и вопросы (011) | `POST /api/reports/<id>/chat` |
| блок подтверждения (только с `#k=`) | какое действие агент хочет сделать, кнопки «Разрешить» и «Отказать» | `GET /api/tasks/<id>/pending`, `POST /api/tasks/<id>/approvals`, заголовок `X-Task-Key` |
| меню Download | JSON сейчас; PDF и журнал сети по пункту 4 из BACKLOG | `report.json`; остальное позже |
| любой другой адрес | «не найдено» | — |

Адреса и ключ во фрагменте не меняются: ссылки, которыми уже поделились, продолжают работать после переключения.

### 3.2 Где живут слова
Сейчас человеческие формулировки собираются на сервере в `views.ts`: словарь `T`, `ageWords`, `countryName`, `confidenceWord`, `findingsList`, тексты ошибок `errorText`, пояснения к «стене» и к предупреждению Cloudflare. В клиенте они становятся модулем `client/src/text/`: функции из данных отчёта в строки, без доступа к сети, с теми же тестами, что сейчас у страниц. Данные приходят только из JSON. Клиент ничего не решает о риске: вердикт, уровни и сигналы приходят готовыми (008, containment 8).

### 3.3 Общий тип отчёта
Клиент берёт тип через `import type { PublicReport } from '../../agent/report.ts'`. Источник правды о форме ответа один, расхождение ловит `tsc --noEmit` в CI. В сборку клиента код агента не попадает: `import type` стирается.

### 3.4 Переход со старых страниц
1. Новый клиент живёт по адресу `/next/...` рядом со старыми страницами, пока не дотянет до них по функциям (список из 3.1 и все тесты страниц из `server/test/app.test.ts`).
2. Переключение: `/` и `/r/...` начинают отдавать `index.html` клиента; `report.json`, `screenshot.png`, `/api/...` не меняются.
3. После недели без возвратов `views.ts`, `static/app.js` и `static/style.css` удаляются вместе с их тестами (тесты API остаются).

## 4. Что запускает
Ничего нового в работе. Код клиента лежит в `web/client/` со своим `package.json` и лок-файлом. `vite build` кладёт файлы в `web/client/dist/`, Hono отдаёт их как статику, а неизвестные пути под `/r/` и `/` — через `index.html`.
Сборка: в CI (артефакт) или на хосте в `deploy/010-web.sh` (`npm ci --ignore-scripts` и `vite build` до замены `$DEST`). Выбор — вопрос 3. На боевом хосте dev-зависимости клиента не нужны, если собирать в CI.

## 5. Интерфейсы
### 5.1 Без изменений
`POST /api/tasks`, `GET /api/tasks/<id>/events`, `GET /r/<id>/report.json`, `GET /r/<id>/screenshot.png?device=`, `POST /api/reports/<id>/chat`, `GET /api/tasks/<id>/pending`, `POST /api/tasks/<id>/approvals`, `GET /healthz`.

### 5.2 Новое
- `GET /api/tasks/<id>` → `{ stage, position, has_report, failed_reason_text }`. Сейчас состояние для первой отрисовки берётся из серверной страницы; в SPA нужен свой источник. Только публичное, без ключа.
- `GET /api/demos` (если не в сборке, вопрос 2).

### 5.3 Расхождения 007 с кодом, найденные при подготовке
- В 007, 3.5 CSP с `form-action 'none'`, в коде `'self'`. Клиент шлёт всё через `fetch`, форм нет, поэтому с ним можно поставить `'none'`, как в спеке.
- В 007, 3.4 событие `final` несёт публичный отчёт целиком, в коде `final` приходит с `{}`, и страница перезагружается. Клиенту хватает `{}`: после `final` он сам запрашивает `report.json`. Спеку 007 поправить под код.

## 6. Ограничения и безопасность (переносится из 007, 3.5 без исключений)
1. Недоверенный текст (поля `UNTRUSTED` из `agent/report.ts`) — только в текстовых узлах. `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `new Function` запрещены; проверяет ESLint (`react/no-danger`, `no-eval`, `no-implied-eval`) в CI.
2. Недоверенный текст никогда не идёт в `href`, `src`, `style`, `srcset`, `action`. Адрес проверяемой страницы и любые адреса из улик показываются **текстом**, не ссылкой. Ссылки клиента строятся только из `task_id` (строгий формат) и своих путей; проверка — тест на враждебном отчёте (раздел 7) и правило ESLint `no-restricted-syntax` на `href={report...}`.
3. CSP остаётся: `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Без `unsafe-inline`, `unsafe-eval` и nonce. Отсюда **закрытый набор компонентов** (замер спайка, раздел 8):
   - можно: Radix Tabs, Tooltip, Popover (по умолчанию немодальный), DropdownMenu **только с `modal={false}`**, нативный `<dialog>` через `showModal()` (свой компонент поверх него вместо Radix Dialog) и нативный `<select>`;
   - нельзя: Radix Dialog и всё, что на нём построено в shadcn (Dialog, AlertDialog, Sheet), DropdownMenu в модальном режиме, Select, а также любой компонент, который блокирует прокрутку через `react-remove-scroll`: они вставляют элемент `<style>` с шириной полосы прокрутки, CSP его блокирует;
   - прокрутку страницы под открытым диалогом останавливает статическое правило в нашем CSS (`html:has(dialog[open]) { overflow: hidden; }`), а не код во время работы;
   - новый компонент добавляется в набор только после прогона проверки CSP в браузере (раздел 7).
4. Ключ задачи читается только из `location.hash`, уходит только заголовком `X-Task-Key`; не попадает в адрес запроса, параметры, состояние маршрутизатора, `localStorage`, журналы и сообщения об ошибках.
5. Ни одного запроса за пределы своего адреса (`connect-src 'self'` это и так запрещает; тест в браузере это проверяет).
6. Скриншот — только `<img src="/r/<id>/screenshot.png?device=…">`, ответ по-прежнему с `Content-Security-Policy: sandbox`.
7. Заголовки 007, 3.5 (`nosniff`, `Referrer-Policy: no-referrer`, `COOP`, `no-store` для отчётов) ставит Hono и для `index.html`.

## 7. Проверка
| Что | Как | Контроль, который обязан упасть |
|---|---|---|
| Экранирование | тест Vitest рендерит каждую страницу на враждебном отчёте (каждое недоверенное поле содержит `"><img src=x onerror=…><script>…`) и требует: в DOM нет `img`, `script`, атрибутов `on*` из этих полей, текст виден как текст | временный `dangerouslySetInnerHTML` в одном компоненте: тест падает, ESLint в CI тоже |
| Ссылки | тест: ни у одного `a` или `img` адрес не взят из недоверенного поля | временный `href={report.url}`: тест падает |
| CSP в браузере | Playwright открывает собранный клиент за настоящим Hono с боевой CSP и требует ноль нарушений CSP в консоли и ноль запросов на чужие адреса | временный внешний шрифт или `style="…"`: тест падает |
| Ключ | тест: после подтверждения ключ есть только в заголовке `X-Task-Key`, его нет в адресах запросов и в хранилищах | временно передать ключ параметром: тест падает |
| Паритет | все тесты страниц из `server/test/app.test.ts` переносятся на клиент до удаления старых страниц | — |
| Типы | `tsc --noEmit` с общим `PublicReport` | поле отчёта переименовано в `agent/`: клиент не собирается |
| Размер | бюджет на сборку (предложение: до 250 КиБ JS после gzip) проверяется в CI | — |
| Глазами | скриншоты каждой страницы на телефоне, планшете и компьютере (тем же Playwright) прикладываются к PR | — |

## 8. Что проверено и что нет
**Спайк, 6 ноября 2026** (ветка `spike/web-client`: `web/client/`, `spike-server.ts` отдаёт сборку за Hono с CSP из 6.3, `spike-check.mjs` проходит настоящим Chromium 158 по каждому компоненту и считает нарушения CSP по отдельности).

Проверено:
- **Сборка:** в `dist/index.html` нет ни одного встроенного скрипта или стиля, только один `.js` и один `.css` со своего адреса. Размер со всем набором: 143,7 КиБ JS и 2,8 КиБ CSS после gzip (бюджет 250 КиБ).
- **Компоненты под боевой CSP:**

  | Компонент | Нарушений CSP |
  |---|---|
  | Radix Tabs, Tooltip, Popover | 0 |
  | Radix DropdownMenu с `modal={false}` | 0 |
  | нативный `<dialog>` (`showModal()`) | 0 |
  | Radix Dialog | 1 (`style-src-elem`) |
  | Radix DropdownMenu по умолчанию (модальный) | 1 |
  | Radix Select | 2 |

  Источник у всех трёх нарушений один: `react-remove-scroll-bar` через `react-style-singleton` вставляет `<style>` с шириной полосы прокрутки в пикселях. Хеш его не разрешит (ширина у каждого своя). Обойти можно только через nonce (`get-nonce`), но тогда `index.html` перестаёт быть статикой, поэтому этот путь не берём.
- **Нативный диалог:** `:modal`, фокус внутри и не уходит на страницу при `Tab`, клик по кнопке за подложкой не доходит, `Escape` закрывает, страница под ним не прокручивается.
- **Набор из 6.3 целиком:** ноль нарушений CSP, ноль запросов на чужие адреса; враждебный текст отчёта (`"><img src=x onerror=…><script>…<style>…`) показан как текст, элементов `img` и `style` из него нет, страница видна. Прямая ссылка на вкладку (`/next/r/<id>/security`) открывается через отдачу `index.html`.
- **Контроль детектора:** атрибут `style`, элемент `<style>` и запрос на чужой адрес, добавленные в работающую страницу, дают по нарушению (`style-src-attr`, `style-src-elem`, `connect-src`). Без этого «ноль нарушений» ничего бы не доказывал.
- **React Router 8:** Data Mode — `createBrowserRouter` из `react-router` и `RouterProvider` из `react-router/dom`; `basename: '/next'` работает для переходного адреса (3.4). Взято из документации, которая лежит в пакете, и проверено сборкой.

Не проверено: компоненты shadcn как таковые (в спайке Radix напрямую с классами Tailwind; shadcn добавляет только классы и обёртки, но каждый взятый компонент всё равно проходит проверку из раздела 7); мобильные браузеры и Safari (только Chromium); поведение Tooltip на сенсорных экранах.

## 9. Открытые вопросы
1. **Внешний вид:** направление (сейчас «в духе Cloudflare Radar»: строгая аналитика; оставить или иначе), тёмная тема, свой цвет. Предложение: сначала макет главной и Summary, согласовать, потом код.
2. Примеры на главной: в сборке клиента (проще) или `GET /api/demos` (меняются без пересборки).
3. Где собирать клиент: в CI с артефактом или на хосте в `010-web.sh`.
4. Язык интерфейса: английский, как сейчас (судьи хакатона); второй язык позже.
5. PDF в меню Download: печатная версия страницы (CSS `@media print`, без новых зависимостей) или файл с сервера.
6. Разделение машин: решено не делать до сдачи; если делать, то по границе привилегий (KVM-хост только с супервизором, всё, что смотрит в интернет, на другом хосте), а не «фронт отдельно» — статика без секретов от переноса почти ничего не выигрывает.
