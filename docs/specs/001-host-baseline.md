# 001. Базовая настройка хоста

Статус: реализовано на сервере (3–4 ноября 2026), проверено после перезагрузки; юниты служб веб-слоя и закрытие входа `root` (4.7) не сделаны.

> Пути на сервере в этой спеке даны в раскладке до 7 ноября 2026 (`/opt/zerostress/...`, `/etc/zerostress`, `/var/lib/zerostress*`). Сейчас всё лежит в каталоге проекта `/zerostress` (`bin/`, `images/`, `config/`, `data/`, `run/`), см. [010](010-layout-and-deploy.md), 4.0.

## 1. Цель и границы
Подготовить один хост (Vultr VM, Rocky Linux 10), на котором безопасно запускаются микро-ВМ Firecracker. Спецификация описывает пользователей, каталоги, права, службы и сетевые настройки хоста. Сеть гостя описана в [003](003-guest-network.md), жизненный цикл микро-ВМ в [002](002-microvm-lifecycle.md).

## 2. Решение
Хост минимален: на нём работают только SSH, файрвол, служба супервизора, служба веб-слоя и прокси. Всё, что исполняет недоверенный контент, живёт внутри микро-ВМ. Привилегированная часть сведена к одной службе и одному маленькому скрипту с фиксированным набором команд.

## 3. Факты о хосте (проверено 3 ноября 2026)
| Параметр | Значение |
|---|---|
| План | Vultr Dedicated CPU VX1, `vx1-g-2c-8g` |
| ОС | Rocky Linux 10.2, ядро 6.12, SELinux Enforcing, cgroups v2 |
| Процессор | AMD EPYC Turin, AMD-V, `kvm_amd nested = 1` |
| Файловая система корня | **ext4** (быстрое копирование `cp --reflink` не поддерживается) |
| Свободное место | около 99 ГБ из 118 ГБ |
| Память | 7,7 ГиБ, своп 8 ГиБ (файл `/swapfile`, не используется) |
| `/dev/kvm` | существует, права `0666`, владелец `root:kvm` (группа `kvm`, GID 36) |
| `/dev/vsock` | существует, модули `vsock`, `vsock_loopback`, `vmw_vsock_virtio_transport_common` загружены, `vhost_vsock` не загружен |
| `firewalld` | активен и управляет nftables (таблица `inet firewalld`); служба `nftables` не активна |
| Слушающие порты | только `sshd` (22, IPv4 и IPv6) |
| `net.ipv4.ip_forward` | 0 |
| Модуль `kvm_amd` | по наблюдению подгружается при загрузке (после перезагрузки `/dev/kvm` существовал без ручного `modprobe`) |
| Пользователь администратор | `linuxuser` (группа `wheel`, не входит в `kvm`) |

## 4. Решения (предложения)

### 4.1 Пользователи и группы
| Пользователь | Назначение | Права |
|---|---|---|
| `zerostress-sup` | служба супервизора, владелец каталогов запусков, запускает процессы Firecracker | группа `kvm`; входит в список `sudoers` только для `zsnet` (см. 003); не имеет оболочки входа |
| `zerostress-web` | служба веб-слоя и привратника | без доступа к `/dev/kvm`, без `sudo`; доступ к сокету супервизора через группу `zerostress-ipc` |
| `linuxuser` | администрирование | как сейчас |

### 4.2 Каталоги
| Путь | Содержимое | Владелец и права |
|---|---|---|
| `/opt/zerostress/bin` | `firecracker`, скрипт `zsnet` | `root:root`, `0755`; служба их не изменяет |
| `/opt/zerostress/images` | образ ядра гостя, базовый образ диска гостя | `root:root`, чтение для `zerostress-sup` |
| `/var/lib/zerostress/runs` | каталог на каждый запуск (сокет, копия диска, журнал) | `zerostress-sup:zerostress-sup`, `0700` |
| `/run/zerostress` | Unix-сокет супервизора | `zerostress-sup:zerostress-ipc`, `0750`, сокет `0660` |

### 4.3 `/dev/kvm`
Ограничить доступ группой `kvm`: правило udev со значением `MODE="0660"`, `GROUP="kvm"`. Сейчас права `0666`, и любой локальный пользователь может создавать виртуальные машины. В группу `kvm` включается только `zerostress-sup`.

### 4.4 Службы systemd
| Служба | Пользователь | Назначение |
|---|---|---|
| `zerostress-supervisor.service` | `zerostress-sup` | управление микро-ВМ, очередь, слушает `/run/zerostress/supervisor.sock` |
| `zerostress-web.service` | `zerostress-web` | публичный веб-слой, привратник, агент; слушает только локальный адрес |
| Прокси | Caddy (решение 4 ноября 2026; под SELinux работает в домене `httpd_t`, порт веб-слоя берём с меткой `http_port_t`) | единственный процесс, слушающий публичный адрес |

Параметры защиты юнитов (предложение): `NoNewPrivileges=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `PrivateTmp=yes`, `ReadWritePaths` только для своих каталогов. Для `zerostress-supervisor` `NoNewPrivileges` несовместим с запуском `sudo zsnet`, поэтому нужно либо отказаться от `sudo` в пользу `AmbientCapabilities=CAP_NET_ADMIN` (шире), либо оставить `sudo` и не включать `NoNewPrivileges`. Решение открыто (раздел 7).

### 4.4a Метка SELinux
Режим Enforcing оставляем. Бинарник `firecracker` сейчас лежит в домашнем каталоге с меткой `user_home_t`; при переносе в `/opt/zerostress/bin` нужна метка выполняемого файла (например, `bin_t`). Служба запускается в домене по умолчанию для нестандартных юнитов; насколько он подходит, не проверено.

### 4.5 Своп и память
Руководство Firecracker для боевого режима рекомендует отключить своп. На хосте 7,7 ГиБ ОЗУ и своп 8 ГиБ без использования. Решение открыто: отключение защищает от тормозов гостей, но снижает запас при пиках. Принять после замеров параллельной нагрузки (см. 002).

### 4.6 Файрвол
Внешний уровень: группа Vultr `ZeroStress`, только входящие правила, по умолчанию всё запрещено. Разрешено: SSH только с адреса администратора, позже 443 для публичного веб-слоя. Исходящие правила группа не задаёт.

Уровень хоста: `firewalld` остаётся включённым. Правила для гостей см. в [003](003-guest-network.md).

### 4.7 SSH
Вход только по ключу, вход под `root` и по паролю выключены, доступ имеет только `linuxuser`.

## 5. Что запускает (разовая настройка, команды в виде плана, не выполнены)
- `useradd`, `groupadd`, `usermod` для пользователей и групп.
- `install -d` для каталогов с нужными правами.
- Запись правила udev для `/dev/kvm` и применение (`udevadm control --reload`, `udevadm trigger`).
- Скачивание Firecracker из официального релиза с проверкой закреплённой контрольной суммы и установка в `/opt/zerostress/bin`; метка SELinux (`semanage fcontext`, `restorecon`). Ядро и образ гостя ставит отдельно `guest/image/install.sh` после сборки.
- Файл `tmpfiles.d` для `/run/zerostress` (каталог на tmpfs пересоздаётся при каждой загрузке).
- Установка юнитов systemd и их включение.

Постоянно работающих процессов, кроме двух служб и прокси, не добавляется.

## 6. Ограничения и ошибки
- Падение супервизора: службы перезапускаются systemd, при старте супервизор находит оставшиеся запуски в `/var/lib/zerostress/runs` и убирает их (см. 002).
- Нехватка места на диске: супервизор отклоняет новые задачи, если свободно меньше заданного порога (значение предлагается позже).

## 7. Проверка
| Проверка | Ожидание |
|---|---|
| `ls -l /dev/kvm` | `crw-rw----`, группа `kvm` |
| Запуск `firecracker --version` от `zerostress-sup` | успешно |
| То же от `zerostress-web` | отказ при обращении к `/dev/kvm` |
| `ss -tlnp` | наружу слушает только прокси и `sshd` |
| `systemctl status zerostress-supervisor` | `active`, права из юнита применены |
| `getenforce` | `Enforcing` |

## 8. Что проверено и что нет
**Проверено:** таблица фактов в разделе 3; Firecracker запускается от обычного пользователя `linuxuser` через `/dev/kvm` с правами `0666`.

**Проверено 3 ноября 2026 на сервере** (скрипт [deploy/steps/10-host.sh](../../deploy/steps/10-host.sh)):
- пользователи `zerostress-sup` (группы `kvm`, `zerostress-ipc`) и `zerostress-web` (группа `zerostress-ipc`), каталоги и права из раздела 4.2, артефакты в `/opt/zerostress`;
- `/dev/kvm` имеет права `0660 root:kvm`: доступ есть у `zerostress-sup`, у `zerostress-web` и `linuxuser` отказ. Правило udev применяется событием `change` с фильтром `--subsystem-match=misc --sysname-match=kvm`; `trigger --name-match` права не меняет;
- Firecracker запущен как транзиентная служба systemd (`systemd-run`, `User=zerostress-sup`) при `Enforcing`: гость (2 vCPU, 1 ГиБ, диск только для чтения) загрузился до приглашения входа, отказов AVC нет.

**Проверено после перезагрузки хоста (4 ноября 2026):** права `/dev/kvm` `0660`, `ip_forward=1`, зона и политика `firewalld`, правило sudoers, пользователи и каталоги сохранились; `SELinux` `Enforcing`; наружу слушает только `sshd`. Каталог `/run/zerostress` после ребута отсутствовал (tmpfs), поэтому добавлен `tmpfiles.d`; повторный запуск скрипта на чистой системе (Firecracker скачивается и проверяется по хешу) прошёл. Скрипт без аргументов воспроизводим; Node и Go на хост ставятся вручную (см. [deploy.md](../deploy.md)).

**Не проверено:** юниты `zerostress-*` и их параметры защиты (`ProtectSystem`, `NoNewPrivileges`); запуск с jailer; запись в диск гостя из службы (проверялся диск только для чтения); отключение свопа под нагрузкой; настройки SSH (раздел 4.7) и файрвол Vultr (раздел 4.6) не менялись.

## 9. Открытые вопросы
1. `sudo zsnet` или `CAP_NET_ADMIN` для супервизора (влияет на параметры юнита).
2. Отключать ли своп.
3. ~~Прокси~~ — Caddy; остаётся домен и проверка выпуска сертификата (на IP через профиль `shortlived` или на домене).
4. Порог свободного места.
