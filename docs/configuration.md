# Configuration

Where each setting lives and what every variable does. Two tests, `web/server/test/env-example.test.ts` and `supervisor/envexample_test.go`, fail if the code reads a variable that is missing from its example file or from this page.

## Where settings live

Everything sits under the project directory: `/zerostress` on a server, your own checkout on a development machine.

| What | File | Template (in git) | Read by | Secret |
|---|---|---|---|---|
| Web layer and agent | `config/web.env` | [config/web.env.example](../config/web.env.example) | the `zerostress-web` service | **yes**: `INFERENCE_API_KEY` |
| MicroVMs and the queue | `config/supervisor.env` | [config/supervisor.env.example](../config/supervisor.env.example) | the `zerostress-supervisor` service | no |
| Proxy | `config/Caddyfile` | [deploy/templates/Caddyfile.tmpl](../deploy/templates/Caddyfile.tmpl) | `caddy` | no; generated by `./zs install`, not edited by hand |
| Versions and checksums | — | [deploy/versions.env](../deploy/versions.env) | the installer, the guest image build | no |
| System files outside the directory (units, sudoers, sysctl, udev, logrotate) | `/etc/…` | [deploy/files/](../deploy/files/) | systemd, sudo, the kernel | no; installed by `./zs install`, not edited by hand |

`./zs config web` (or `supervisor`) opens the file in an editor and restarts the service. `./zs verify` checks the variable names against the template without printing any values. `config/*.env` is git-ignored. In the templates, uncommented lines are set on purpose and commented ones show the default.

There are two files rather than one because only the web service may read the model key (no secrets anywhere else, and never in the guest): `config/web.env` is `root:zerostress-web`, mode `0640`.

On a development machine: `cp config/web.env.example config/web.env`, add a key if you want the model, then `./zs dev`.

## web.env

### Model (Vultr Serverless Inference)
| Variable | Default | What it does |
|---|---|---|
| `INFERENCE_BASE_URL` | empty (template: `https://api.vultrinference.com/v1`) | OpenAI-compatible API address; `https` only (plain `http` only for your own machine) |
| `INFERENCE_API_KEY` | empty | the key; empty means no model and a rules-only verdict |
| `INFERENCE_MODEL` | empty (template: `qwen3.8-27b`) | the model, chosen by a benchmark on the live service |
| `INFERENCE_VISION` | empty | `1` lets the model see the page screenshot too |
| `AGENT_MODEL` | empty | `off` turns the model off whatever is set above |
| `AGENT_MODEL_THINKING` | empty | `default` lets reasoning models reason (costs tokens); otherwise they are asked not to |
| `AGENT_MODEL_TIMEOUT_S` | 30 (1–300) | timeout of one request |
| `AGENT_MODEL_MAX_TOKENS` | 2000 (200–16000) | answer size limit |
| `AGENT_MODEL_RETRIES` | 2 (0–5) | retries on failure |
| `AGENT_MODEL_CONCURRENCY` | 8 (1–16) | model requests in flight at once |
| `AGENT_DAILY_REQUESTS` | 2000 | daily request budget for the whole service; past it, verdicts are rules-only |
| `AGENT_DAILY_TOKENS` | 4000000 | daily token budget |
| `AGENT_MAX_STEPS` | 5 (0–20) | agent actions in one deep check |

### Cloudflare URL Scanner (second opinion)
A second opinion on pages the sandbox could not read because of a bot wall. Cloudflare's scanner gets through most bot protections (measured on 7 November 2026: 3 of 4 walled sites), though not an explicit "verify you are human" widget. On the free plan every scan is **public** at Cloudflare, so a new scan of a visitor's link is only sent with their consent. Looking for an existing scan sends the exact link to Cloudflare's search (it is not published); that happens only when the owner of a report asks for a second opinion. A scan still running when the answer is due is polled on the next ask, never sent twice, and the whole service sends at most 50 new scans a day.

| Variable | Default | What it does |
|---|---|---|
| `CF_URLSCANNER_ACCOUNT_ID` | empty | the Cloudflare account id (32 hex characters) |
| `CF_URLSCANNER_TOKEN` | empty | an account-scoped API token with *Account > URL Scanner > Edit* (*Radar Read* only reads); a secret like the model key |

Both empty turns it off. One without the other, or a value of the wrong shape, stops the service at start; the error never repeats the value.

### Service
`<root>` is the directory two levels above `web/server/`: `/zerostress` on a server, your checkout on a development machine.

| Variable | Default | What it does |
|---|---|---|
| `WEB_PORT` | 8080 | port on `127.0.0.1` (reachable from outside only through Caddy) |
| `WEB_DATA_DIR` | `<root>/data/web/tasks` | finished reports (kept 24 hours) |
| `WEB_CLIENT_DIR` | `<root>/build/client` | the built interface |
| `SUP_SOCKET` | `<root>/run/supervisor.sock` | the supervisor's socket (the supervisor reads it too, see below) |
| `WEB_DEMOS` | `A harmless page\|https://example.com/` | example buttons under the address field, `label\|url;label\|url` |
| `GEO_DIR` | `<root>/data/geo` | DB-IP Lite tables; without them no countries are shown |
| `WEB_RDAP` | empty | `off` stops domain-age lookups |

### Limits
| Variable | Default | What it limits |
|---|---|---|
| `WEB_LIMIT_PER_HOUR` | 5 | new checks per visitor address per hour |
| `WEB_LIMIT_PER_DAY` | 20 | per day |
| `WEB_LIMIT_ACTIVE` | 1 | checks running at once per visitor address |
| `WEB_LIMIT_STREAMS` | 4 | open progress streams per visitor address |
| `WEB_LIMIT_DAILY_CAP` | 300 | checks per day for the whole service |
| `WEB_LIMIT_CHAT_PER_HOUR` | 20 | chat requests per visitor address per hour |
| `WEB_LIMIT_CHAT_PER_REPORT` | 12 | questions about one report |

## supervisor.env

The supervisor refuses to start with a value out of range (`supervisor/config.go`).

| Variable | Default | What it does |
|---|---|---|
| `SUP_CONCURRENCY` | 2 (1–4; template: 2) | microVMs at once; 2 was chosen by measurement on the host |
| `SUP_QUEUE_MAX` | 20 | queue length |
| `SUP_QUEUE_WAIT_S` | 120 | how long a job may wait in the queue |
| `SUP_BOOT_TIMEOUT_S` | 15 | microVM boot timeout |
| `SUP_HARD_TIMEOUT_S` | 90 | total time limit of a plain check |
| `SUP_VCPU` | 2 (1–4) | vCPUs per microVM |
| `SUP_MEM_MIB` | 1024 (256–4096) | memory per microVM |
| `SUP_MIN_FREE_GB` | 20 | below this much free disk, new runs are refused |
| `SUP_RESULT_TTL_H` | 24 | how long run results are kept |
| `SUP_SESSION_SLOTS` | 1 (0–4) | live sessions (deep checks) at once; 0 turns them off |
| `SUP_SESSION_IDLE_S` | 60 | close a session after this much idle time (the clock stops while a command waits for a human) |
| `SUP_SESSION_MAX_S` | 300 | maximum session lifetime |
| `SUP_SESSION_GRACE_S` | 30 | time allowed for closing a session |
| `SUP_APPROVAL_TTL_S` | 300 | how long a risky command waits for a human decision |
| `SUP_COMMAND_MAX` | 190 | commands in one run |
| `SUP_COMMAND_TIMEOUT_S` | 30 | timeout of one command |
| `SUP_STATE_DIR` | `/zerostress/data/supervisor` | state: run directories, results, the database (the `zsvm` helper has its `…/runs` path built in) |
| `SUP_IMAGE_DIR` | `/zerostress/images` | the guest image |
| `SUP_KERNEL` | `<SUP_IMAGE_DIR>/vmlinux-6.18.56` | the guest kernel |
| `SUP_ZSNET` | `/zerostress/bin/zsnet` | network helper (run through sudo) |
| `SUP_ZSVM` | `/zerostress/bin/zsvm` | microVM launch helper (run through sudo) |

`SUP_SOCKET` (default `/zerostress/run/supervisor.sock`) is read by both services: the supervisor creates the socket, the web layer connects to it.
