# Готовые инструменты: что есть, что берём, что нет

Составлено 4 ноября 2026. Четыре исследователя читали первоисточники (репозитории, документацию, карточки моделей, ленты релизов), часть данных я перепроверил сам. Это справочник, чтобы не держать список в памяти: по каждому инструменту указано, что он даёт именно нам, лицензия, актуальность и решение.

**Как читать пометки.**
- **(✔)** — проверено мной лично при составлении (реестр, API, пакет, поиск по первоисточнику).
- Без пометки — из отчёта исследователя, который читал первоисточник; даты версий на 2026-11-04.
- **(❓)** — не подтверждено ни исследователем, ни мной. Лимит GitHub API закрыл часть проверок дат, поэтому у ряда проектов даты последнего коммита не указаны.
- Условия использования и лимиты сервисов меняются без предупреждения: перед сдачей их нужно перечитать.

Решения: **берём** (использовать), **смотрим** (оценить, прежде чем брать), **идея** (взять подход, не код), **нет** (не использовать).

## 2. Анализ ссылок и репутация (сигналы для вердикта)

Главное ограничение: условия использования. Для публичного демо подходят не все источники, а полные ссылки пользователей нельзя отправлять третьим лицам (в них бывают личные токены).

## 10. Что из этого меняет наши решения

1. **Спецификация 005:** проверить `ariaSnapshot({mode:'ai'})` вместо собственной нумерации `ref` (снимки `iframe` включены, ссылки готовые). Нужно убедиться, что снимок содержит скрытый текст или хотя бы не прячет его от хуков.
2. **Контроль расходов Vultr Inference:** собственный код-привратник с дневным лимитом и счётчиком токенов, не LiteLLM.
3. **Слой против инъекций:** после детерминированных правил оценить Prompt Guard 2 (22M для английского, 86M для многоязычного) на CPU, ONNX и по памяти; оценка моделей и стойкости через promptfoo и garak, плюс собственный корпус страниц-инъекций.
4. **Дополнительные сигналы вердикта** (без утечки ссылок): Tranco, dnstwist, RDAP, URLhaus как локальный фид после уточнения условий.
5. **Гигиена образа и репозитория:** Syft и Grype вместо Trivy на корневой системе гостя, osv-scanner на lock-файлах, gitleaks до публикации, закрепление Actions по полному SHA.
6. **Вложения:** ClamAV не поместится в ВМ на 1024 МиБ по заявленной загрузке сигнатур (выводится из отчёта, замер нужен); YARA-X и exiftool лёгкие; идея Dangerzone (рендер в пиксели) стоит отдельной проработки.
7. **Прокси и HTTPS для публичного адреса:** Caddy или HAProxy не выбраны. Критерии: как получить доверенный сертификат (домен или IP), нужны ли ограничения по IP на уровне прокси (у HAProxy встроены, у Caddy нужен сторонний модуль; в любом случае ограничения будут и в нашем привратнике веб-слоя), поведение долгих потоков SSE. Решает короткий опыт на сервере: выпуск сертификата в тестовой среде Let's Encrypt (требует открытых портов 80 и 443 снаружи) и нагрузка потока SSE через оба прокси. Запасной путь для HTTPS — собственный домен; `sslip.io` и `nip.io` не основной вариант.
8. **Firecracker:** пока на последней версии; следить за релизами, снапшоты не считать переносимыми между версиями.
9. **Материалы для сдачи:** Marp CLI (PDF слайдов, Chrome на машине разработки), D2 для диаграмм, VHS для видео терминала.

## 11. Не подтверждено (собрано в одном месте)

- Поддержка IP-сертификатов `shortlived` в Caddy, минимальная версия Caddy, доступность профиля для нашего аккаунта.
- Условия обновления сигнатур ClamAV, реальный расход памяти `clamscan` в госте.
- Скорость и память Prompt Guard 2 на CPU и в ONNX; детали обхода Prompt Guard в препринтах 2512.11783 и 2510.09023.
- Качество и размеры моделей OCR для кириллицы и CJK; нужен ли браузер D2 для PNG.
- Лицензии: PlaywrightCapture, CAPEv2, Cloud Hypervisor, asciinema, firecracker-go-sdk; даты последних коммитов ряда проектов.
- Квоты Web Risk, цифры бесплатного плана urlscan.io (только сторонние источники), лимиты Spamhaus и RDAP, SURBL.
- Хронология взлома LiteLLM и точное число затронутых тегов Trivy (источники расходятся); текст предупреждения Aqua не читался.
- CVE для Chromium 156 в связке с Playwright 1.64.1.
- Какие бэкенды изоляции у OpenSandbox; соответствует ли модель `nemotron-3.5-content-safety` в листинге Vultr модели NVIDIA.
